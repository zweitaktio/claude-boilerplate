### 3. `git add -A` contradicts four other rules

**File:** `core/process/engineering-discipline.md:163`

Step 5 of § Implementation Process tells the agent to run:

```bash
git add -A && git commit -m "checkpoint: before refactoring auth middleware"
```

Four instructions forbid exactly this command:

| File | Line | Text |
|------|------|------|
| `core/process/tooling.md` | 182 | "never `git add -A` / `git add .`" |
| `core/process/multi-agent.md` | 120 | "never `git add -A`" |
| `references/bootstrap-template.md` | 63 | "never `checkout`, `stash`, `reset`, or `git add -A`" |
| `.claude/rules/git.md` | — | the same prohibition for this repository |

`engineering-discipline.md` and `tooling.md` both load on every session. The memory documentation names
this failure: two files give different guidance, and Claude picks one arbitrarily.

**The command is wrong, and so is the whole step.** A checkpoint commit needs a path list that the agent
does not have. It wants to save whatever is dirty. On a shared tree that dirty set belongs to several
sessions. `--only` does not rescue the step either: `tooling.md:186` records that `--only` fails on a
file git has never seen, which covers every new file in unfinished work.

Corrected text for step 5:

> 5. **Rollback readiness** — before a risky edit, commit the files you are about to change, by name.
>    ```bash
>    git commit --only src/auth/middleware.ts -m "checkpoint: before refactoring auth middleware"
>    ```
>    Add a new file with `git add <path>` first, because `--only` cannot resolve an untracked path.
>    Never sweep the tree. Dirty files you did not touch belong to another session.

**Bump:** minor on `core/process/engineering-discipline.md`.

## S4 — Practices the documentation supports and the templates lack

### 17. State the reason with the instruction

The prompting guidance states that context or motivation behind an instruction improves adherence. Its
example is exact:

- Less effective: `NEVER use ellipses`
- More effective: `Your response will be read aloud by a text-to-speech engine, so never use ellipses since the text-to-speech engine will not know how to pronounce them.`

The guidance adds: Claude generalizes from the explanation.

`core/claude-config/writing-rules.md` has no such rule. Several repository rules already give the reason,
and they are the better ones. Add the pattern with this example.

### 18. Adopt the published over-engineering block

The prompting guidance publishes a ready block that limits scope creep. It covers four areas: scope,
documentation, defensive coding, and abstractions. Your `engineering-discipline.md` covers one of the
four in a single anti-pattern bullet.

Add the four areas to § Anti-Patterns.

### 19. Add degrees of freedom to the rule-writing guidance

The skill authoring guidance names a design axis your writing rules lack. Match the level of specificity
to the fragility of the task. High freedom suits a task with several valid approaches. Low freedom suits
a fragile task with one correct sequence.

This explains when a forced artifact is right, and when it is over-specification.

### 20. Add the Opus 5 delegation cap

The Opus 5 guidance states that Opus 5 delegates to subagents more readily than earlier models.
Delegation multiplies cost on small tasks. The guidance tells you to give explicit criteria, or to set
deterministic caps.

Claude Code adds its own delegation instruction on Opus 5 only under the `claude_code` system prompt
preset. A deployed rule set cannot rely on that.

Two environment variables set the caps: `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` and
`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`. They need Claude Code 2.1.217 or later.

Add the criteria to `core/process/multi-agent.md`. Add the two variables to
`core/claude-config/claude-settings.md`.

### 24. The code reviewer is now adversarial and audits the gates

`agents/code-reviewer.md` was a persona with a report template. It is now a procedure.

- **`model: fable`.** The subagent frontmatter accepts `sonnet`, `opus`, `haiku`, `fable`, a full model
  ID, or `inherit`.
- **Two passes.** Pass 1 builds a case against the change and maps the call graph. Pass 2 falsifies each
  candidate with the `FALSIFY:` artifact from `core/code-change-gates`. Only survivors reach the report.
- **Verdicts.** Each finding carries `CONFIRMED` or `PLAUSIBLE` and names the evidence checked. A
  candidate that a guard, a caller or a type defeats is dropped, and listed under "Dropped in
  verification".
- **It audits the four gates.** `INTENT:`, `TWINS:`, `FALSIFY:` and `AUTH:` are claims, not formalities.
  The reviewer re-runs the `TWINS:` search, opens the source the `INTENT:` line cites, checks that the
  `FALSIFY:` third slot holds evidence, and confirms the `AUTH:` quote authorizes the action. A missing
  gate is a finding. A written gate that fails verification is a worse finding.
- **Input contract.** The subagent never sees the parent conversation. `core/engineering-discipline`
  § Review Gate now requires the parent to pass the changed paths, the task, and every gate line.
- **Two-axis classification.** Six categories, borrowed from CodeRabbit's content badges, crossed with
  the existing Critical, High, Medium and Low severities from `core/code-review`.
- **A suppression list.** Anything `yarn check` catches, unchanged code, style preference, a finding with
  no failure scenario, and praise. An empty report is a valid result.

## Applied — rule 11, the filler rule

`core/interaction` § Language gained rule 11:

> Keep an intensifier, a frequency adverb or a qualifier only when it changes the technical outcome.
> **Test:** delete the word, re-read the sentence, keep it only if the meaning changed.

It is a deletion test, never a word ban. It ships in four places: the rule table in
`core/process/interaction.md`, the per-turn reminder in `.claude/hooks/prompt-context.mjs`, the project
overlay in `.claude/rules/interaction.md`, and `references/bootstrap-template.md`.

`scripts/ste-check.mjs --filler` lists candidates. Rule 11 needs judgment, so it advises and never
gates the exit code.
